Title: Operating Systems: Concurrency, Deadlocks, and Memory Management

1. Processes vs. Threads:
   - A process is an executing program instance with its own private virtual address space (code, data, heap, stack), file descriptors, and security attributes.
   - A thread is the smallest unit of CPU scheduling within a process. Threads in the same process share the heap, data, and code segments, but possess distinct program counters (PC), registers, and stack pointers.
   - Context Switching Overhead: Thread context switching is significantly faster than process context switching because the Memory Management Unit (MMU) does not need to invalidate the Translation Lookaside Buffer (TLB) or reload page directory base registers (CR3 in x86).

2. Critical Section Problem & Synchronization:
   - Race Conditions arise when multiple threads access and mutate shared mutable state without synchronization.
   - A valid solution must satisfy three criteria:
     a) Mutual Exclusion: Only one thread can be in the critical section at a time.
     b) Progress: If no thread is in the critical section and some wish to enter, selection cannot be postponed indefinitely.
     c) Bounded Waiting: A bound must exist on the number of times other threads enter their critical sections after a thread has requested entry.
   - Synchronization primitives: Mutexes (binary lock), Counting Semaphores (Dijkstra's P/wait and V/signal), Condition Variables, and Read-Write Locks.

3. Deadlocks:
   - A deadlock occurs when a set of processes are permanently blocked because each process holds a resource and waits for another resource held by another process in the set.
   - Coffman's Four Conditions (all must hold concurrently for deadlock to occur):
     1) Mutual Exclusion: At least one resource is held in a non-shareable mode.
     2) Hold and Wait: A process holding at least one resource is waiting to acquire additional resources.
     3) No Preemption: Resources cannot be forcibly seized from a process.
     4) Circular Wait: A closed chain of processes exists such that each process holds a resource that is needed by the next.
   - Prevention/Avoidance: Banker's Algorithm evaluates resource allocation requests to ensure the system remains in a 'Safe State'. Resource hierarchy ordering breaks the circular wait condition.

4. Virtual Memory & Paging:
   - Virtual addresses generated by the CPU are mapped to physical DRAM addresses by the MMU using hierarchical page tables.
   - Page Faults trigger an OS trap when the Present/Valid bit in the page table entry is zero, requiring disk I/O to swap the page from backing store into physical memory.
   - Replacement Algorithms: FIFO, LRU (Least Recently Used), and Clock (Second Chance). Thrashing occurs when a process lacks sufficient working set frames, causing the CPU to spend more time servicing page faults than executing instructions.
